# 1.8.0 大爷骑火箭与贴边收起验证

按项目AGENTS的Addy强制流程执行调试、增量实现、UI、行为回归、独立审查及版本发布。范围见[本版规格](spec-1.8.0.md)。本次仅用Android模拟器和自有测试接收App，没有操作真实京东账号或订单。

## 复现与修复

正式1.7.0使用实际全局拖动后，新UI层级中左侧浮窗为`[0,1401][192,1593]`，宽192px（64dp）；4dp窄边要求对应12px，断言实际失败并保存截图。原实现只做完整方块的边缘对齐，没有收起状态。

现在保持同一个View，拖动松手将实际宽度缩为4dp，左右边缘位置按窄边宽度计算，高度保留所选32～120dp。点窄边先展开，原来的连续三击开关监听器不被调用；收起/展开清空连击且计时起点不变。收起不绘制电话/计时，真实触摸和Back排除区域也只有4dp；无障碍描述仍提供开关和展开提示。大小和可见度独立。

主页面和真实WindowManager控制器原生检查已通过：左右收起、首击展开不切换/不计入三击、32/120dp收起状态调尺寸、同一View/计时/可见度、取消和多指、仅可见区域手势排除、状态操作不派发订单。最终构建已通过收起停留1100ms的计时连续断言、实际展开文本检查及API34+移动动画策略断言。

## 实际系统窗口动画

第一次全局检查不能简单算通过：LayoutParams与frame已显示左侧12px窄边，但系统`ContainerAnimator`仍有400ms移动动画，截图实际窄边还在x164，立即点x6未展开。保留该失败及动画证据，避免只检查请求坐标而漏掉实际显示。另一次初步探针曾要求拖动后的Y必须精确等于指令终点，实际触摸最后MOVE采样存在差异；正式验收检查屏幕内边界及展开前后Y保持，而非强行等同命令坐标。

API34及以上通过公开[setCanPlayMoveAnimation](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#setCanPlayMoveAnimation(boolean))关闭状态窗口的移动动画，保持显示窄边与可点击位置同步。API24～33保留系统默认行为，不使用隐藏接口，也不将API37结果外推为所有旧系统立即完成。

修复后的非instrumentation真实服务窗口，全局输入检查通过。左窄边`(0,795)(12x192)`点一下恢复`(0,795)(192x192)`；右窄边`(1068,890)(12x192)`点一下恢复`(888,890)(192x192)`，即4dp/64dp对应宽度，展开前后Y不变。四份窗口记录没有系统move animation，接收App保持前台；即时截图也确认窄边位于屏幕边缘。原失败日志保留，未覆盖成通过。
