# 1.6.0 三单同屏与电话浮标验证

按`AGENTS.md`强制Addy流程执行；需求汇总见`spec-1.6.0.md`。本次只使用虚构订单、自有测试接收App和Android模拟器，没有操作真实京东账号或订单。

## 结果

- 找字页每轮三单。唯一普通样式田只在第一或第二单地址道路名称中，第三单/标题/备注无田；每次刷新全部字段继续更新。
- 360dp宽和320dp宽、640dp高的默认字体竖屏检查通过：三张完整卡片和48dp手动滑条全部在视口内，没有第四张，地址不省略、不裁剪。错单、成功和刷新后再次核对同屏条件。大字体/横屏保留自然滚动回退，不能从这两种竖屏结果推广所有尺寸。
- 电话浮标28×28dp，约原面积五分之一；不透明黑色背景由整体alpha调节，绿色听筒为自绘路径。开启下方正向计时，关闭只有听筒；菜单10%/55%/100%及重开保存通过，默认10%。
- 开启超过一秒后实际`TextView.getText()`推进；同状态轮询或修改可见度不重置，关闭文本清空且计时停止，再开启从零开始。时间以单调`elapsedRealtime`为基准，每次刷新只读一次快照；分钟、小时及超过24小时格式有主机测试。[Android时钟说明](https://developer.android.com/reference/android/os/SystemClock)
- 保留三击、音量键、拖动/取消/多指清除连击；浮标拖动松手吸附最近物理边缘。实际服务窗口验证了左右避让、拖动期间轮询不覆盖坐标、可见度和计时更新，没有产生新订单手势。

## 先失败再修复及互审

- 模型旧六单失败于`three orders fit one practice screen`。改三单后500种子验证唯一田、首两单地址限制、道路名称位置、紧凑长度、全部新字段、统计/重试/容量等通过。临时把候选数2改3会失败，正式源码未受影响。
- 旧页面即使只有三单，第一张卡底部也超出视口，设备断言实际失败；压缩说明和卡片后通过。没有通过截掉地址来制造同屏。
- 原84×48dp及过渡36×22dp分别被新尺寸断言拒绝，最终28×28dp通过。
- 将“重复开启不重计”的条件临时改为每次开启都重计，设备测试按预期失败于`opacity or repeated same-state updates must not restart the counter`；立即恢复源码并完整重建、安装、复跑通过。
- 计时测试曾仅检查即时计算getter，互审加强为同时检查实际显示文本，防止界面回调失效仍通过。
- 生成器、UI、服务/主页面、计时回调与新测试均接受作者以外的五轴审查；没有Required/Critical遗留项。手势路径、时长、固定目标、锁屏及一次派发限制没有新增自动操作。

## 实际全局输入与系统返回手势

直接调用View控制器的测试不能覆盖系统边缘返回。补充实际全局合成输入时，确认Main在前台后从右侧浮标向内拖动，系统Back确实关闭Main，保留了失败截图和前后台记录。

修复按Android标准API29+仅将浮标自身矩形声明为系统手势排除区域，没有扩大到其他区域或禁用全局返回。[Android手势导航说明](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav)

最终Main实际右→左、左→右全局拖动均保留Main前台并吸附正确。另在非instrumentation进程、自有接收App前台的真实无障碍窗口验证两方向：WindowManager中84×84px浮窗由`(996,640)`移至`(0,843)`，再到`(996,938)`；接收App始终前台。实际截图确认关闭态只有电话。这里是模拟器的全局合成触摸链路，不是实体手机手指或压力验收。

既有跨应用浮标集成用例也通过：单/双不切换、三击开关不派发、一次真实夹具滑动后回到关闭、离开目标和熄屏隐藏。一次连续复用instrumentation时在服务连接前失败，未算通过；恢复服务开关后重新启用夹具服务，完整用例通过。
