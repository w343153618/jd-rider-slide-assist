# 1.10.0 关键词提醒模拟验证

日期：2026-11-01。按项目AGENTS的Addy规格、增量实现、先失败再通过、五轴独立审查、文档和发布流程实施。[本版规格](spec-1.10.0.md)约定6～8张虚构订单、整批匹配、纯手动滑条及可停止的1200ms红色呼吸。

## 实现与验收范围

- Main新增显式入口，独立页面默认关闭提醒；打开即停止原辅助和记录。仅处理本App自己生成的订单字段，不调用截图、OCR或真实客户端订单接口，不增加权限和运行时依赖。
- 每批6～8单，三个简称独立随机出现。匹配标题、地址、货品、备注的全部已加载数据，屏幕外订单也参与；控制面板规则文字不参与匹配。
- 所有滑条复用纯手动的ManualSpeedSliderView，点击/按住不完成，必须手动到达98%并抬手；原DemoSliderView在85%后有自动补齐，因此没有在本页复用。红色层不截获触摸，抬手200ms后复位。
- 首帧红色22%，随后4%～22%平滑呼吸，1200ms一周期；系统关闭动画时静态12%。API26+使用公开areAnimatorsEnabled，API24～25读取公开动画设置并只在可见提醒期间观察变化，读取受限时静态回退。
- 顶部开关/返回固定；无命中、关闭、离开和分离窗口停止动画。旋转保留实际当前批及开关。进程重建只保留种子和开关并据此重新生成；防重复字段回退还依赖上一批，因此不保证逐字恢复原批，且本次未做进程重建运行验收。

## Android模拟器运行

API37、1080×1920、density480、默认字体。只使用虚构订单与独立fixtureCheck包；以下均不代表真实京东客户端或实体手机验收。

```sh
adb shell am instrument -w -e v110keyword 1 com.example.slideassist.testfixture.test/com.example.slideassist.GestureInstrumentation
```

正常系统动画和系统animator_duration_scale=0各运行一次，均通过；外层测试保存并在finally恢复原设置（当次原键不存在，恢复删除该键）。用例检查：

- 入口、默认关闭、显式开启；三个简称、全批无命中、自身规则标签不误触发。
- 唯一命中在第五单之后、可见订单文字无关键词时仍提醒；滚到底部返回按钮仍可见。
- 红层实际绘制像素有透明红色变化；关闭动画时无运行Animator且为静态12%。测试检查的是渲染输出，没有将一个布尔状态当作呼吸效果证据。
- 通过Activity触摸分发向完整窗口发送DOWN/MOVE/UP：按住和轻点白色手柄不完成，全行程手动拖动能穿透红层完成，且不会意外刷新或采集原始轨迹。
- 下拉提交新的6～8单与变化文字；停止/后台/恢复/重建/返回清理，重建保留实际批次且旧动画释放。

受影响回归v15main、v15reaction、v19edge均通过，保留十一档模拟时长、固定返回、三单找字及20dp浮窗把手交互。v19edge为直接控制器事件检查，不冒称跨应用全局输入验证。

另外用adb全局触摸操作实际可见界面：开启无关键词的8单批次后没有红层，下拉换为6单且南邮命中的批次后红层出现；当前可见前两单均无学校简称。红层保持期间从第一单白色手柄滑到末端，页面累计“手动完成1次”，随后自动复位。真实界面截图及新鲜UI层级仅保存在忽略的本地产物目录，没有用静态设计稿代替运行画面。

## 物理与客户端边界

API24～25动画偏好的兼容路径通过SDK编译及代码审查，本次没有对应系统镜像的运行证明。设备重建测试调用Activity.recreate，验证保留批次和释放旧动画，不代表已实测横竖屏布局切换或进程终止恢复。纯数据匹配的测试不能证明真实客户端可读、OCR准确率或50/100ms完整提醒延迟。

真实客户端优先尝试其向系统公开的文字节点，见Android的[AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)。若只有画面像素，可评估经用户授权的本地画面识别；[ML Kit](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)支持直接处理Bitmap、media.Image或字节缓冲，不必保存截图文件。节点未公开和内容尚未加载/显示时不能据此承诺读到屏幕外订单。没有逆向私有接口、绕过保护、隐藏服务、Root或防封号验收。
