# 1.9.0 把手抓取与拖出还原验证

遵循项目AGENTS的Addy调试、增量实现、UI、先失败再通过的行为测试、独立审查和版本流程。[本版规格](spec-1.9.0.md)记录20dp把手、35%收起可见度下限和12dp向内展开等交互约定。仅使用Android模拟器、虚构订单和自有接收App。

## 有效失败与原因

正式1.8.0从右侧4dp细边实际向内拖动，松手后新UI层级仍为`辅助已关闭，已折叠，轻点展开 [1068,864][1080,1056]`，宽12px（4dp），期望的64dp完整窗口未还原，断言失败。旧控制器在拖动松手后无条件再次收起，也没有MOVE阶段展开转换。运行计时的初步UIAutomator探针无法等待idle，未作为新页面证据；停止计时后使用新XML获得以上有效RED。

纯策略测试也先拒绝旧4dp值，再实现20dp、方向/阈值、自由位置与可见度下限。隔离变异反转向内方向、移除35%下限均被测试拒绝，未污染正式源码。

## 原生与全局结果

- 最终V19 Main及真实WindowManager服务测试通过：左右12dp向内MOVE立即展开、左侧抓取偏移/右侧距右边偏移连续、UP保持完整自由位置、普通点击及三击不回边、外推到边缘才收起、把手竖向拖动、取消/多指恢复原状态、32/120dp尺寸、同一View计时及35%/10%显示切换，原始偏好值保持10%。
- V16与V18 Main/服务回归均通过。旧用例改为从有效自由位置向目标边缘外推后检查收起，不再把“在任意位置松手必吸边”的旧行为作为要求；尺寸、计时、连击、取消和排除范围等断言保留。
- 服务测试在每个三击步骤前及结束时检查手势诊断，避免重新开启重置诊断而掩盖之前异常；加强后V19服务用例再次通过。
- 非instrumentation实际全局触摸通过：右把手`(1020,640)(60x192)`向内拉后为`(742,640)(192x192)`，左把手`(0,640)(60x192)`向内拉后为`(178,640)(192x192)`，对应20dp/64dp。两次单击后完整窗口位置均保持不变，没有系统移动动画；接收端无新增完成滑动。即时及稳定帧截图分开保留，稳定把手箭头清晰。
- 实际窗口/测量后的View/Back排除区域匹配当前可见范围。没有创建隐藏的大块触摸区，没有新订单派发路径；真实辅助条避让仍可为安全调整Y，不把这种避让误写成自动吸边。
