# 1.5.0 实现约定

用户已授权开始本版本。按项目强制 Addy 流程，以可验证的小步骤实现和审查。

## 能力与验收

1. 模拟滑条和手动测试滑条在一次操作结束后等待200ms自动复位；手指仍按住时延后到抬手再开始等待，避免在一次触摸中重触发。复位只恢复练习控件，不清空次数/报告、不触发新操作。真实页面辅助保持一次人工触发至多一次派发。
2. 模拟订单页增加50/60/70/80/90ms，保留100/150/200/250/450/700ms。模拟时长单独保存，默认250ms；真实页原有时长设置独立，手动测试不用自动时长。
3. 手速测试与找字反应测试均有固定在顶部的“返回模拟抢单”，滚动到报告末尾也可返回。
4. 独立找字反应测试页每轮6张虚构订单，文字长短不同、可上下滚动；下拉刷新替换全部订单文字，恰有一个普通样式的“田”随机嵌入其中。开始测试前不采集、没有计分；不自动识别或替用户选单。
5. 按已确认的方式，找字与手速测试均由本人手动拖动白色手柄，到98%行程并抬手为成功。每批只有首次正确完成计分；重复滑动可练习但不重复计分。错误订单、无效起点、多指、取消、未完成、刷新放弃、离开页面分别记录。
6. 报告分别显示呈现到正确目标按下、按下到首次位移、按下到98%、呈现到98%、终点后抬手；正确目标首次按下与最终成功尝试分别保留。累计平均/中位/P95/最快/最慢/标准差、前后批次比较、错误/重试以及滚动距离和方向变化。呈现起点使用应用帧回调，不冒充实际屏幕出光或眼球注视；目标字符首次进入可见区域只作布局估计。
7. 复用已有等比轨迹、逐点数据、慢放回放和曲线；找字尝试使用独立`reaction_manual`来源，不混入独立手速榜。保留设备原始pressure/size等；人体电流、真实物理力、硬件/网络/订单接受时间未提供时明确缺失。
8. 本地显式启用采集，可停止并通过系统文件选择器导出JSON/CSV；反应会话最多50轮/200尝试，原始点沿用200次/每次1024点/总20000点，超限显式计数。进程退出数据丢失，旋转不伪造新计分轮次。

## 分工和验证顺序

- 先复现未自动复位和缺少快速档位；实现控件并做设备回归。
- 独立单元验证随机内容、唯一目标、计时有效性、首次计分、错误排除、边界/上限与统计数学。
- 接入本地页面，设备验证下拉、手动滑动、轨迹报告、返回按钮、停止/离开/旋转和导出。
- 对改动做独立代码审查，修复必改项；完整构建、host tests、Lint和既有模拟/跨应用夹具回归后，使用同签名发布新版本。验收证据区分测试夹具、正式安装包和真实骑士App。

200ms是最早进入消息队列执行的延时，实际复位还受UI线程和刷新帧调度影响；不承诺物理屏幕恰好在200ms复位。
