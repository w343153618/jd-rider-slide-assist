# 1.11.0 逐单静态学校颜色标记验证

日期2026-11-01。遵循项目AGENTS的Addy规格、TDD、增量实现、UI、五轴独立审查和版本流程。[最终规格](spec-1.11.0.md)按用户最新要求取消全屏闪烁，保留白底并只标记对应订单。

## 最终实现

- 移除旧全屏RedBreathingView，不将开发中曾尝试的整屏多色带发布。每张卡片自己的左侧5dp窄条仅用来显示本单匹配学校，无动画、计时器或系统动画设置观察，不覆盖文字和滑条。
- 南邮红#dc2626、南航绿#15803d、南理工蓝#2563eb；同单多校的局部窄条分段、全部标签并列，原文实际关键词用对应深色。顶部按学校列出全部命中订单编号，同校同单只列一次。
- 原始四字段用于匹配，标签/说明/摘要不回流匹配；关闭和后台使订单窄条透明，清除卡片/摘要颜色跨度。固定三色说明保持颜色，不能把它当作实际命中。纯手动、200ms复位、下拉6～8单、已加载屏幕外检查、固定返回等保留。
- 生成器各学校仍独立35%决定本批是否出现，再分到1～2张不同订单，不同学校可以共享同一订单。保持每批同位四字段变化、有界回退、不可变批次和种子重现。

## 先失败再通过及独立审查

- Palette缺类、深色文字缺API的聚焦测试先RED后GREEN；独立硬编码三色、深色、颜色名，验证去重规范顺序、未知/null和不可变快照。对比度计算包括当前白/灰底上的关键词深色；不据此宣称整页全部无障碍验收。
- 生成器分别捕获旧实现不能同单多校、同校多单的RED；保留原500种子及差异/不可变测试，增加4096种子覆盖同单两校/三校、各校单独出现、同校最多两张不同订单及同址不重复。
- 原生先捕获南航单色仍为红色的失败；用户随后取消全屏，按最终契约再次捕获旧全屏覆盖层仍存在的失败。替换旧全屏断言依据是用户明确改变需求，新的测试必须检查无全屏层、局部实际颜色和白底，不以删除失败断言代替验证。
- 独立审查提出小字颜色在整屏覆盖下对比不足、内部色带描边压文字，以及操作后卡片丢失编号三个问题。前两项由移除整屏层及采用深色文字解决；原生先捕获手动完成后丢失编号的RED，再将回调修为“模拟订单 N · 手动完成 X 次”。固定orderNumber避免循环捕获错误，短文案避免额外换行移动滑条。
- 不同作者分别交叉审查模型、调色和新静态界面；临时反转Palette选择和强制生成器只放一单的变异均被测试检出，变异没有进入共享源码。
