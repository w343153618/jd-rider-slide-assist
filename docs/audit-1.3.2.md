# 1.3.2 缺陷检查与修复记录

检查日期：2026-10-31。按 addyosmani/agent-skills 的 code-review-and-quality、debugging-and-error-recovery、test-driven-development 流程，结合独立只读审查和 Android 模拟器运行。审查对象为已交付的1.3.1及本次修复。

## 已复现并修复

### 模拟页完成一单后不能继续点击其他订单

原实现为了模拟真实辅助的一次性开关，在动画开始和完成时都关闭了模拟辅助；这不符合连续练习需求。新回归在旧源码上明确失败：`second demo order must complete without re-enabling assistance`。

修复后，模拟页保持用户选择的开关状态，完成一单只更新这一单；其他订单仍需本人分别点击，已完成订单可通过实际重置按钮再次练习。手动关闭状态球仍会停止点击辅助。

模拟页完整回归通过，覆盖连续两单、保持开启、实际重置按钮、手动关闭后两个订单都不响应辅助点击、重新开启继续、起点区域判定、按下/抬起/双击/双指及移动/三指误触、六档设置和700毫秒动画与持久化。真实服务和状态球的独立跨应用回归也通过；真实辅助每次触发仍只派发一次滑动，结束后关闭。

### 返回更新授权页面后，旋转屏幕丢失待安装入口

原实现返回授权设置就清除持久记录，核验/安装确认期间重建 Activity 后无法恢复已下载更新。新增用例使用同一签名、较高版本的独立 fixture APK，旧实现明确失败：`verified ready update must remain persisted after permission return`。

修复后，待安装记录保存到明确取消、文件无效或成功打开系统安装器为止。重建后重新核验摘要、包名、递增版本和签名，并再次要求用户确认。兼容原先的 waiting 记录，没有静默安装路径。

Android 测试通过：有效更新从授权恢复后保留记录；实际执行 Activity.recreate 后再次显示安装确认；稍后/取消清除记录；篡改已存字节后恢复会被拒绝并清记录；缺少安装来源权限时只显示本 App 的授权提示，不打开安装器。允许和拒绝权限下的无效记录回归均通过。

## 重现新增生命周期测试

先构建、安装 fixtureCheck 和 androidTest，准备同一 fixture 包名/签名且版本高于测试安装的 APK 到 `/data/local/tmp/slide-valid-update.apk`（本次私有测试文件为9.9.9/code999，不安装或发布）。在隔离模拟器上分别预设 fixture 安装来源权限 allow / ignore 后运行；改变授权可能杀进程，故每种权限单独启动 instrumentation。

```sh
adb shell am instrument -w -r -e lifecycle 1 \
  com.example.slideassist.testfixture.test/com.example.slideassist.GestureInstrumentation
```

测试会核验前置权限状态，创建并清理自己持有的文件，不操作生产应用。隔离测试结束已恢复测试前无障碍 null/0、fixture 安装授权 default，adb 为普通 shell，临时测试 APK 已删除。
